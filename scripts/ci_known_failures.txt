# Baseline известных падающих тестов (регресс-гейт, reserc.md #104).
# Предсуществующие падения/ошибки на момент уборки 'нет CI'.
# В основном устаревшие тесты / frontend-drift / ожидания старых флагов —
# это НЕ регрессии прода. CI зелёный, если НЕТ новых падений сверх этого списка.
# Baseline принадлежит профилю CI, а не машине разработчика: расхождение из-за
# отсутствующего optional-датасета чинится тестом, а не перезаписью списка.
#
# ─── Владельцы и сроки (требование G0, W0-INT-01) ───────────────────────────
#
# Каждая запись обязана иметь владельца, задачу закрытия и срок пересмотра:
# долг без владельца не сокращается, а зарастает. Ниже записи сгруппированы
# по ПРИЧИНЕ, потому что у 33 из 35 причина одна.

# ── Группа 1: тесты норм не исполняются — отказ на setup (33 записи) ────────
#
# Причина установлена волной 0.0.03 и она НЕ та, что была записана здесь
# раньше. Прежняя редакция утверждала: записи существуют только из-за
# отсутствия norms/vault и после provisioning обязаны исчезнуть. Это неверно,
# и оставлять такое утверждение в baseline нельзя — оно назначает не того
# владельца и обещает закрытие долга от события, которое на него не влияет.
#
# Что измерено. Все 33 узла падают на setup фикстуры с AttributeError:
# tests/test_norms_status_index_fallback.py монкейпатчит у
# norms.external_provider атрибуты NORMS_DB_PATH, NORMS_VAULT_PATH и
# MISSING_NORMS_VAULT_PATHS, которых у модуля нет (__all__ провайдера —
# NORMS_STATUS_INDEX_PATH, load_status_index, resolve_norm_status; сам
# NORMS_DB_PATH живёт в norms/_core.py). `git log -S NORMS_VAULT_PATH --
# norms/external_provider.py` пуст: этих атрибутов у провайдера не было
# никогда. Отказ наступает за доли секунды, ДО любого обращения к файловой
# системе, а сами тесты работают на tmp_path и синтетических деревьях.
#
# Следствия, которые обязаны быть названы прямо:
#   * появление norms/vault не изменит ни одного из 33 исходов;
#   * пока записи висят в baseline, 33 теста нормативного контура не
#     проверяют ничего, и зелёный гейт это маскирует;
#   * прежнее условие пересмотра «при первом же успешном provisioning»
#     недостижимо в принципе.
#
# Записи оставлены нетронутыми намеренно: правкой baseline это не лечится, а
# правка тестов или провайдера меняет контракт fallback-провайдера — это
# отдельная задача с собственным владельцем, а не уборка CI. Тесты никогда не
# были зелёными, поэтому неизвестно, какие из них пройдут после починки, а
# какие вскроют дефект провайдера; оценка этого — часть той же задачи.
#
#   владелец: владелец нормативного контура (tests/test_norms_status_index_fallback.py
#     и norms/external_provider.py)
#   задача закрытия: привести тест и провайдер к одному контракту; после этого
#     записи уходят из baseline по факту зелёного прогона — не по факту корпуса
#   пересмотр: следующая волна после 0.0.03; проверка одной командой —
#     `python -m pytest tests/test_norms_status_index_fallback.py`
#
# Про norm corpus отдельно. Он остаётся обязательным для enforce по §3.3, но к
# этим 33 записям отношения не имеет. Источник владельцем не назван; шаг CI
# «Provisioning norm corpus» переведён волной 0.0.03 в source-agnostic
# fail-closed режим и ждёт конфигурации. Что обязан предоставить владелец —
# docs/ops/NORM_ARTIFACT_SOURCE.md. norms/tools/README.md по-прежнему прямо
# запрещает собирать vault из norms_db.json: это внешний вход.
