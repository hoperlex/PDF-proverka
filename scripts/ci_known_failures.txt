# Baseline известных падающих тестов (регресс-гейт, reserc.md #104).
# Предсуществующие падения/ошибки на момент уборки 'нет CI'.
# В основном устаревшие тесты / frontend-drift / ожидания старых флагов —
# это НЕ регрессии прода. CI зелёный, если НЕТ новых падений сверх этого списка.
# Baseline принадлежит профилю CI, а не машине разработчика: расхождение из-за
# отсутствующего optional-датасета чинится тестом, а не перезаписью списка.
#
# ─── Владельцы и сроки (требование G0, W0-INT-01) ───────────────────────────
#
# Каждая запись обязана иметь владельца, задачу закрытия и срок пересмотра:
# долг без владельца не сокращается, а зарастает. Записи сгруппированы по
# ПРИЧИНЕ: так видно, что закрывается одной задачей, а что разными.
#
# Кол-во: 0

# ── Закрыто волной 0.0.03: группа «тесты норм» (было 33 записи) ─────────────
#
# История оставлена намеренно: она объясняет, почему счётчик группы упал сразу
# на 33 и почему это НЕ перезапись baseline под красный прогон.
#
# Записи держались не на том, на чём было записано. Прежняя редакция этого файла
# утверждала: причина — отсутствующий norms/vault, и после provisioning записи
# исчезнут. Проверка опровергла: все 33 узла падали на setup фикстуры с
# AttributeError, потому что тест монкейпатчил у norms.external_provider
# атрибуты (NORMS_DB_PATH, NORMS_VAULT_PATH, MISSING_NORMS_VAULT_PATHS),
# которых у модуля не было никогда. Тест был написан под четырёхклассовый
# fallback-провайдер, резолвящий нормы из norms_db.json, — то есть ровно под
# тот legacy-контур, который norms/tools/README.md запрещает прямым текстом.
#
# Поэтому чинились ТЕСТЫ, а не провайдер: дописать в провайдер недостающие
# атрибуты значило бы вернуть запрещённый fallback. Тесты переписаны под
# фактический контракт status_index-only, проверки классификации уровня _core
# вынесены в tests/test_norms_core_classification.py.
#
# Записи сняты по зелёному ПРЯМОМУ прогону, а не по факту появления корпуса:
#   python -m pytest tests/test_norms_status_index_fallback.py \
#                    tests/test_norms_core_classification.py
#
# Восстановленные тесты сразу нашли три дефекта самого провайдера (ложный
# authoritative-матч по обрывку кода, неоднозначный префикс, чужой alias поверх
# собственного кода) — они исправлены там же и закрыты регрессами. Разбор —
# в docs/architecture/receipts/W0-INT-01.json.

# ── Baseline ПУСТ с 2026-09-03 ──────────────────────────────────────────────
#
# Записей нет. Это не «список потеряли», а состояние: весь известный долг по
# тестам разобран поимённо, а не списан.
#
# Как он пустел:
#   33 записи группы «тесты норм» — не переписью списка, а починкой тестов.
#     Они падали на setup фикстуры с AttributeError, потому что были написаны
#     под запрещённый legacy fallback-провайдер. Переписаны под фактический
#     контракт status_index-only; заодно вскрылись и закрыты три дефекта резолва.
#   1 запись WEB (`versions-panel`) — устаревший characterization contract:
#     коммит 91f48104 намеренно удалил панель версий, а проверка пережила
#     удаление. Разведена на две: «удалённое отсутствует» и «уцелевшее на месте».
#   1 запись ENG (critic v2) — тест был КРАСНЫМ С РОЖДЕНИЯ: он и политика
#     `_TAXONOMY_NO_REJECT` появились одним коммитом 29d3a0bf, и продукт никогда
#     не вёл себя так, как требовала проверка. Фикстура приведена к действующей
#     политике и разведена на квалифицированный и неквалифицированный reject.
#
# Что это меняет для CI: полоса и гейт теперь краснеют на ЛЮБОМ падении, потому
# что известного долга не осталось. Пустой baseline — самое строгое состояние из
# возможных, и удерживать его дешевле, чем восстанавливать.
#
# Если запись придётся добавить снова — она обязана нести владельца, задачу
# закрытия и срок пересмотра, как того требует G0. Запись без владельца не
# сокращается, а зарастает; ровно так группа «тесты норм» и прожила лишний год
# с неверно назначенной причиной.
