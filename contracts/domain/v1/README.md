# Domain contract v1: машиночитаемая форма

Машиночитаемая форма контракта идентификаторов, состояний и ошибок нового
контура. Источник истины — `docs/architecture/DOMAIN_CONTRACT_V1.md`: файлы
каталога повторяют его таблицы и ничего к ним не добавляют.

| Файл | Что описывает | Раздел источника |
| --- | --- | --- |
| `identifiers.json` | синонимы, формы, реестр ID, ключи, алиасы | §2—§3.4 |
| `states.json` | четыре машины состояний, вердикты, `severity` | §4.2—§4.7 |
| `errors.json` | конверт, статусы, связь с gRPC, каталог кодов | §5.1—§5.4 |
| `error_envelope.schema.json` | JSON Schema конверта (draft 2020-12) | §5.1 |

## Владение

Владелец — lane ARC: словарь, идентичность и состояния. Соисполнитель —
lane API: конверт ошибки и каталог кодов. Потребитель (`W1-META-01`,
`W1-STO-01`, `W1-API-01`) схему в своей задаче не меняет: правка идёт через
владельца (ADR-0003).

## Правило согласия

Действует правило «markdown и JSON не расходятся». Меняется сначала markdown,
затем в том же коммите — JSON. Нормативного содержания сверх markdown здесь
нет: формы, префиксы, владельцы машин, начальные значения и статусы
вычисляются из его таблиц.

## Как проверяется

Тест `tests/test_domain_contract_v1.py` сверяет с markdown имена, значения,
префиксы и regex, проверяет достижимость состояний и запрет выхода из
терминальных, каталог кодов и конверт §5.1, а также согласие с `GLOSSARY.md`
§2.1 и `contracts/agent_stream/v1/common.proto`.

## Версионирование

Каталог `v1` — версия контракта. Новое необязательное поле или новый
`error_code` версию не повышают. Удаление кода, смена его смысла, сужение
списка значений состояния и переименование поля требуют каталога `v2`
отдельной integration task (§7 источника).
