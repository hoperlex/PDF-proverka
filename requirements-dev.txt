# Тестовый/CI-профиль центра — то, что ставится в clean-room по §4.2 п.1
# quality/runtime contract v1.
#
# ПОЧЕМУ ОТДЕЛЬНЫЙ ФАЙЛ, А НЕ СТРОЧКА В requirements.txt.
# requirements.txt описывает РАБОТАЮЩИЙ центр: на проде нет ни одного запуска
# pytest, и тащить туда test runner значит расширять поверхность продакшена
# ради удобства CI. Обратная ошибка дороже: до W0-OPS-03 pytest не был объявлен
# НИГДЕ, и чистое окружение, собранное строго по манифестам, не могло запустить
# ни одного теста («No module named pytest», находка CR-1). Тест-раннер — такая
# же зависимость, как и любая другая: не объявлена — значит, её нет.
#
# ПОЧЕМУ ЭТОТ ФАЙЛ — ЕДИНСТВЕННАЯ ТОЧКА ВХОДА В ТЕСТОВОЕ ОКРУЖЕНИЕ.
# Инвентарь тестов покрывает не только центр: контрактные тесты компилируют
# .proto (grpcio-tools), тесты шлюза импортируют grpcio-health-checking, тесты
# агента — httpx/psutil. Раньше это собиралось перечислением шести `-r` в
# командной строке, и порядок/состав перечисления жил в чужой памяти, а не в
# репозитории. Здесь состав зафиксирован, а версии приходят из
# constraints-qr-v1.txt.
#
# УСТАНОВКА (ровно одна команда, §4.2 п.1):
#   python -m pip install -c constraints-qr-v1.txt -r requirements-dev.txt
#   python -m pip check
#   python -m pip freeze | sha256sum   # 557e95885700a4… §4.1
#
# ЧЕГО ЗДЕСЬ НЕТ И ПОЧЕМУ: requirements-worker-pipeline.txt.
# Он описывает конвейер на СТОРОННЕМ VPS и осознанно прибивает другой набор
# (fastapi 0.115.6, starlette 0.41.3, pydantic 2.10.4, openai 2.31.0). §4.1
# контракта прямо запрещает складывать worker-манифесты с центральными:
# «test lock включает нужные пакеты в версиях qr-v1, не меняя worker production
# profile». Именно это слепое сложение и дало находку CR-2 — центр в
# clean-room поднимался на fastapi 0.115.6 вместо 0.141.1, и снапшот
# HTTP-контракта расходился на 27 эндпоинтов. Библиотеки, которые конвейеру
# нужны на самом деле (PyMuPDF, pillow, openpyxl, passlib), объявлены там, где
# им место, — в requirements.txt центра.

# ── что ставится ─────────────────────────────────────────────────────────────
-r requirements.txt              # сам центр
-r requirements-worker.txt       # агент: httpx, psutil
-r requirements-worker-grpc.txt  # overlay Agent Stream v1 (включает worker)
-r requirements-gateway.txt      # процесс шлюза 12B
-r requirements-proto.txt        # grpcio-tools для contracts/agent_stream/v1

# ── собственно инструменты разработчика/CI ───────────────────────────────────
# Версии не пишем: их назначает constraints-qr-v1.txt. Здесь — только факт
# необходимости, чтобы у одной версии был один источник истины.
pytest                 # раннер всего инвентаря; pytest.ini рассчитан на его маркеры
pytest-asyncio         # async-тесты (backend/tests/**, tests/test_*_async*)

# Сборочные пакеты. В Python 3.12 `venv` их больше не кладёт, а часть колёс
# ставится из sdist и требует backend'а сборки; кроме того, они входят в
# reference freeze §4.1 — без них SHA-256 окружения не сойдётся с эталоном.
setuptools
wheel
