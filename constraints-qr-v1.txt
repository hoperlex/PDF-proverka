# Материализованный dependency lock профиля `qr-v1`
# (contract `quality-runtime/v1`, docs/architecture/QUALITY_RUNTIME_CONTRACT_V1.md §4.1).
#
# ПОЧЕМУ ОТДЕЛЬНЫЙ КАТАЛОГ, А НЕ ОДИН constraints.txt В КОРНЕ.
# Профилей окружения в репозитории заведомо больше одного: центр/CI живут на
# tuple `qr-v1`, а requirements-worker-pipeline.txt осознанно держит ДРУГИЕ
# пины под сторонний VPS (§4.1: «worker/gateway manifests не складываются слепо
# с center requirements... test lock включает нужные пакеты в версиях qr-v1, не
# меняя worker production profile»). Имя файла обязано называть профиль, иначе
# следующий lock придётся вносить в тот же безымянный constraints.txt и молча
# смешивать два несовместимых набора. Каталог оставляет для второго профиля
# место, а `-c constraints-qr-v1.txt` в команде читается как утверждение о том,
# КАКОЙ рецепт воспроизводится.
#
# ПОЧЕМУ ЗДЕСЬ ВЕРСИИ, А В МАНИФЕСТАХ — ТОЛЬКО ИМЕНА.
# Разделение полномочий: requirements*.txt отвечают на вопрос «что нужно этому
# развёртыванию», а этот файл — «какая ровно версия проверена». Из-за этого
# верхние границы манифестов остаются осмысленными (они выражают знание о
# несовместимости), а воспроизводимость не зависит от даты установки.
#
# СОДЕРЖИМОЕ. 62 строки ниже — дословно `Полный reference freeze` из §4.1,
# порядок и написание имён сохранены. Проверка целостности:
#   sed -e '/^#/d' -e '/^$/d' constraints-qr-v1.txt | sha256sum
#   # 557e95885700a44013febcc6559fa8ee278923507b71df8adba761e1e247f99c
# Это тот же SHA-256, который §4.1 требует от полного вывода `python -m pip
# freeze` в собранном окружении: файл и рецепт совпадают побайтно, поэтому
# расхождение видно без ручного сличения.
#
# КАК ПРИМЕНЯТЬ (clean-room/CI, §4.2 п.1):
#   python -m pip install -c constraints-qr-v1.txt -r requirements-dev.txt
#   python -m pip check
#   python -m pip freeze | sha256sum
#
# ЧЕГО ЭТОТ ФАЙЛ НЕ ДЕЛАЕТ. Constraints не устанавливают ничего сами: пакет
# попадает в окружение, только если его требует какой-нибудь манифест. Поэтому
# lock не заменяет манифесты и не «чинит» пропущенную зависимость — он лишь
# запрещает резолверу выбрать непроверенную версию.
#
# НЕ ПРИМЕНЯТЬ К requirements-worker-pipeline.txt: там прибиты fastapi 0.115.6,
# starlette 0.41.3, pydantic 2.10.4, openai 2.31.0 — установка под этим lock
# даст конфликт версий, и это правильное поведение, а не поломка. Профиль
# воркерного конвейера переводится на qr-v1 отдельной задачей с прогоном на VPS.
