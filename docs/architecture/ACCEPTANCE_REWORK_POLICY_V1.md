# Ограниченная приёмка и rework v1

**Policy ID:** `acceptance-rework/v1`

**Статус:** enforced

**Действует с:** 2026-09-07

Эта политика запрещает неограниченный цикл «полная проверка → сопутствующая
правка → полная проверка». Она применяется к task, integration slice,
checkpoint, gate, release candidate и production cutover с момента входа в
формальную приёмку. Обычный TDD до заморозки кандидата остаётся внутри
implementation и не расходует попытки приёмки.

Машиночитаемые числовые ограничения находятся в
[policy contract](policies/acceptance-rework-v1.json). При расхождении текста и
JSON действует более строгое ограничение; расхождение обязано красить
document-contract tests.

## 1. Неизменяемый вход

До первого полного regression gate интегратор фиксирует в task card или
receipt:

- `acceptance_window_id` и владельца решения;
- полный `candidate_sha`;
- `allowed_paths`, `non_goals` и версии frozen contracts/fixtures;
- точную команду полного гейта и обязательные preflight-команды;
- статус `candidate_frozen`.

Передача нового SHA, расширение `allowed_paths`, смена contract/fixture или
добавление результата в scope означает новый кандидат. После первой попытки
такая смена разрешена только как единственный remediation commit по §4.

## 2. Preflight до дорогого прогона

Полный гейт не запускается, пока не зелёные:

1. тесты непосредственно изменённых модулей и контрактов;
2. formatter/linter/typecheck, относящиеся к изменённым файлам;
3. обязательные capability/dependency probes;
4. проверки целостности fixtures, ссылок и JSON, если они затронуты.

Известно красный preflight — это implementation defect, а не «первая попытка,
чтобы посмотреть остальные ошибки». Его исправляют до заморозки либо уменьшают
scope. После зелёного preflight кандидат фиксируется и открывается окно
приёмки.

## 3. Жёсткий бюджет окна

На одно окно разрешены:

- максимум **2** запущенных полных гейта;
- максимум **1** remediation round между ними;
- **0** автоматических повторов;
- максимум **1800 секунд** на каждый полный гейт;
- максимум **15 минут** на классификацию результатов после получения
  пригодного отчёта.

Попыткой считается любой старт полного гейта: passed, failed, timeout,
cancelled, setup error, неполный/устаревший JUnit и непригодное окружение.
Повтор «потому что, возможно, flaky» также является следующей попыткой.

Смена коммита отменяет незавершённый CI старого кандидата. Одновременные полные
гейты разных ревизий одного PR/ветки запрещены.

## 4. Классификация и допустимая правка

Каждая находка первой попытки получает ровно один класс:

| Класс | Значение | Действие в текущем окне |
| --- | --- | --- |
| `candidate_regression` | вызвана изменением кандидата и находится в frozen scope | допускается один remediation commit и финальная попытка |
| `pre_existing_or_flaky` | воспроизводилась до кандидата либо доказан недетерминизм | отдельная задача; кандидат не расширяется, baseline/skip не меняются |
| `environment_or_evidence` | setup, capability, источник данных, JUnit или provenance непригодны | окно завершается как `blocked_external`; автоматического повтора нет |
| `out_of_scope_improvement` | улучшение, не требуемое outcome текущей задачи | backlog; не правится до завершения окна |
| `security_or_data_blocker` | риск утечки, потери данных, локаута или невоспроизводимого rollback | окно завершается как `rejected` или `split`; исправление оформляется новым уменьшенным кандидатом |

В том же окне запрещено:

- расширять outcome или `allowed_paths`;
- делать попутный refactoring/cleanup;
- обновлять зависимости или contract без прямой связи с
  `candidate_regression`;
- скрывать находку через baseline, skip, xfail или ослабление assertion;
- чинить старый/flaky тест ради зелёного цвета кандидата.

Если причина не классифицирована за 15 минут, окно останавливается. Агент не
делает серию предположительных правок.

## 5. Вторая попытка — финальная

После единственного remediation commit сначала повторяются затронутые targeted
checks. Только когда они зелёные, запускается второй полный гейт.

- второй гейт зелёный — кандидат `accepted`;
- второй гейт неуспешный по любой причине — окно получает один из терминальных
  статусов: `split`, `rejected` или `blocked_external`;
- третья попытка в том же окне запрещена.

Новое окно после лимита может открыть только человек-владелец явным решением.
Решение называет причину, новый уменьшенный scope и новый
`acceptance_window_id`; оно не является автоматическим продолжением старого
окна.

```text
implementation → green preflight → candidate_frozen → full gate #1
                                                   ├─ pass → accepted
                                                   └─ fail → classify
                                                             ├─ не candidate regression → terminal stop
                                                             └─ one remediation → targeted checks → full gate #2
                                                                                              ├─ pass → accepted
                                                                                              └─ fail → terminal stop
```

## 6. Когда полный гейт не повторяется

После зелёного source candidate отдельный commit с receipt, publication state,
ссылками или поясняющей документацией не открывает новый полный regression
gate. Для него выполняются document-contract/receipt checks и проверка связи с
исходным SHA. Полный прогон обязателен снова только если изменились исполняемый
код, test fixtures, dependency/CI/runtime configuration или нормативный
contract, влияющий на поведение.

CI опубликованного commit остаётся обязательным release evidence, но новый
commit отменяет устаревший прогон той же ветки и не разрешает параллельную
«гонку кандидатов».

## 7. Минимальная запись решения

Task card или receipt окна содержит:

```text
policy_id: acceptance-rework/v1
acceptance_window_id:
owner:
candidate_sha:
frozen_scope: {allowed_paths, non_goals, contracts, fixtures}
preflight: [{command, result, evidence}]
attempts: [{number, source_commit, result, evidence}]
findings: [{id, class, evidence, disposition}]
remediation_commit: null | <sha>
terminal_status: accepted | split | rejected | blocked_external
next_task_ids: []
```

Отсутствие записи не обнуляет счётчик попыток. Если доказать число уже
запущенных гейтов нельзя, окно считается исчерпанным и останавливается.

## 8. Ответственность

Интегратор замораживает scope и ведёт счётчик. Исполнитель исправляет только
разрешённую `candidate_regression`. CI ограничивает длительность одного прогона
и отменяет устаревшие запуски. Человек-владелец единственный может открыть
новое окно после лимита.

Ни срочность, ни стоимость уже выполненной работы, ни желание получить зелёный
статус не являются основанием для третьей попытки.
