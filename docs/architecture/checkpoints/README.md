# Квитанции чекпоинтов

Чекпоинт — **воспроизводимое состояние**, к которому можно вернуться и от
которого можно независимо раздавать задачи. Это не то же самое, что gate.

| | Gate (G0–G5) | Чекпоинт (CP) |
| --- | --- | --- |
| Отвечает на вопрос | можно ли идти дальше | какое состояние зафиксировано |
| Результат | пройден / не пройден | captured, с честным статусом качества |
| Может быть красным | нет: не пройден — значит стоп | да: состояние фиксируется как есть |

Красный чекпоинт — нормальное явление. Он фиксирует исходную точку, но
**не разрешает следующий cutover**: за это отвечает `authorizes_next_cutover`.
Если ждать устранения всех дефектов, чекпоинт превращается в gate и перестаёт
быть точкой возврата.

## Собственные имена

Нумерация гейтов не дублируется. Свои имена получают только точки, которые
гейтами не являются:

| Чекпоинт | Что фиксирует |
| --- | --- |
| `CP0` | baseline: исходное состояние до любых изменений программы |
| `CP1` | safe legacy: redaction, auth, watchdog захвачен в репозиторий |
| `CP2` | evidence freeze: все инвентаризации и fixtures волны 0 готовы |
| `CP4` | lane-ready: отдельный компонент W1 готов к интеграции |
| `CP6` | pre-canary RC: shadow пройден, релизный коммит заморожен |

Гейты `G0`–`G5` сохраняют свои номера и просто выпускают квитанцию того же
формата. Отдельных идентификаторов `CP3`/`CP5`/`CP7` не существует.

## Формат

Квитанция — машиночитаемый JSON `CP<N>.json`. Обязательный минимум:

- `checkpoint_id`, `checkpoint_status`, `quality_gate`, `verdict`,
  `authorizes_next_cutover`;
- `source_commit` — именно **проверенный** коммит. Квитанция коммитится
  отдельно и следующей, иначе возникает самоссылка;
- `repository_parent` — предыдущий коммит репозитория. Это **не** production
  rollback target: production-откат живёт в release-манифесте, а не здесь;
- `environment_profile` — версии рантайма и наличие внешних зависимостей;
- `test_receipt` — команда, коды возврата, полнота сбора, счётчики, пути и
  хеши отчёта и baseline;
- `known_defects`, `open_exceptions` (с owner и expiry), `cleanup_receipt`.

## Правила

1. Квитанция описывает то, что измерено, а не то, что планировалось.
2. Числа берутся из артефакта прогона, а не из комментариев в файлах.
3. Недетерминированные результаты перечисляются поимённо, а не усредняются.
4. Отсутствующие данные помечаются явно с указанием, кто и когда их доставит —
   пустое поле не выдаётся за ноль.
5. До observation чекпоинт не разрешает удалять rollback-копии, старые blob'ы,
   JSON-проекции и compatibility-флаги (P-11).
