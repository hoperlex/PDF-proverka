# ADR-0005. Контрактные волны для параллельной вайб-разработки

**Статус:** accepted<br>
**Дата:** 2026-08-27<br>
**Владельцы:** technical lead, integrator каждой волны<br>
**Утверждено:** заказчик, 2026-08-27; требование независимых parallel agent/vibe tasks<br>
**Supersedes:** нет<br>
**Затронутые принципы:** P-04, P-10, P-11, P-13

## Контекст

Несколько исполнителей работают в одном checkout без per-task branches и
worktrees. Параллельные изменения общих contracts и hotspots создают больше
конфликтов и скрытых расхождений, чем полезного ускорения.

## Решение

Работа организуется волнами:

1. один contract-task фиксирует schema/API/event version;
2. provider, consumer, tests, migration и operations задачи выполняются
   параллельно в непересекающихся каталогах;
3. один integration-task соединяет результаты;
4. canary evidence закрывает волну;
5. следующая версия контракта начинается только после гейта.

Одна задача имеет один измеримый результат, frozen inputs, allowed paths,
non-goals, локальную проверку и rollback/feature mode. Общие файлы принадлежат
интегратору. Предпочтительный размер задачи — 0,5–3 инженерных дня.

## Последствия

- независимость задач проверяется до старта, а не во время merge;
- часть работы становится явными contract/integration tasks;
- параллелизм временно ниже в волне 0, но выше и безопаснее после фиксации
  границ;
- WIP ограничивается числом реально независимых ownership zones.
