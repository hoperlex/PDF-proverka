## 0. Что этот документ делает и чего не делает

Делает: заводит форму матрицы применимости, вносит в неё положения стандарта,
для каждого фиксирует решение с обоснованием и владельцем, и отдельно проверяет
вторую половину условия G0 №10 — сплошным проходом по всем 18 ADR.

Не делает: не закрывает условие G0 №10 (см. §7 — decision timeout не запущен),
не переводит ни один ADR в `accepted`, не меняет реестр внешних входов, не
назначает сроки от имени владельца программы и не придумывает положения,
которых нет в найденном тексте.

## 1. Главный факт: текст стандарта найден в истории git

Первое, что требовалось установить, — есть ли текст стандарта. Результат:

| Что | Значение |
| --- | --- |
| Файл | `corp_standard_short_single_vps.md` (в корне репозитория) |
| Состояние в рабочем дереве | **отсутствует**, удалён 2026-07-16 |
| Коммит добавления | `0ccba600` |
| Коммит удаления | `d6b9e9bf` «chore(docs): удалить выжимку корп. стандарта single-VPS» |
| Blob (неизменяемый адрес текста) | `8de3f5bc4f80de6aebdd7715d345c7418588efeb` |
| Объём | 438 строк, 12 разделов |
| Как достать | `git show d6b9e9bf^:corp_standard_short_single_vps.md` |

**Это меняет исходную посылку задачи.** В рабочем дереве текста нет, и по
поиску live-файлов вывод «текста нет» был бы правильным. Но текст
**восстанавливается из истории** и содержит конкретные, цитируемые положения.
Поэтому матрица ниже заполнена реальными положениями, а не заглушками.

**Однако это не полный стандарт.** Файл озаглавлен «Краткая **выжимка**
корпоративного стандарта v3.1: single-VPS baseline». Отсюда три ограничения,
которые нельзя обойти:

1. **выжимка ≠ стандарт.** Разделов, не попавших в выжимку, может быть сколько
   угодно (процессы, тестирование, code review, SLA, договорная часть). Из
   отсутствия темы в выжимке **не следует** её отсутствие в стандарте;
2. **нумерации оригинала нет.** В выжимке разделы 1–12 — её собственные.
   Ссылаться на «пункт N стандарта v3.1» нельзя; ниже ссылки даны на разделы
   выжимки с явной пометкой;
3. **актуальность по-прежнему не подтверждена.** Реестр внешних входов
   ([`ADR_INDEX.md`](ADR_INDEX.md), раздел «Внешние нормативные входы») говорит:
   «рекомендательный; актуальность не подтверждена, новой редакции нет».
   Найденный текст этого не меняет: найден **текст**, а не **подтверждение**.

Копии, упомянутой в сообщении коммита `d6b9e9bf`
(`.claude/worktrees/new-upload-format-stage1/`), на диске нет — проверено
поиском по всему дереву `/root/projects/PDF-proverka`.

## 2. Форма матрицы: колонки и правила заполнения

### 2.1. Колонки

| Колонка | Что содержит | Правило |
| --- | --- | --- |
| **ID** | `ST-NN` | сквозной, не переиспользуется при удалении строки |
| **Положение** | формулировка стандарта своими словами, без домысливания | если положение в тексте отсутствует — строка не заводится |
| **Источник упоминания** | раздел выжимки + место в документах программы, если оно есть | ссылка на blob `8de3f5bc`, раздел выжимки; ADR/док программы |
| **Решение** | одно из пяти значений §2.2 | ровно одно; «частично» не является решением — строка делится |
| **Обоснование** | почему именно это решение, со ссылкой на проверяемый факт | ссылка на ADR/файл/измерение, а не на предпочтение |
| **Владелец** | кто вправе изменить решение | роль или задача; «программа» владельцем не является |
| **Срок пересмотра** | дата либо событие-триггер | «—» допустимо только при решении `принять` без внешней зависимости |

### 2.2. Словарь решений

- **принять** — положение действует для программы как есть; расхождений с
  принятыми решениями нет либо решения программы уже строже;
- **адаптировать** — принимается принцип, заменяется реализация (обычно
  потому, что стандарт называет Node/JS-инструмент, а контур программы —
  Python); в обосновании обязателен эквивалент;
- **отложить** — область положения в волнах 0–1 не существует; решение
  переносится на событие-триггер;
- **отклонить** — положение противоречит принятому решению программы либо
  относится к чужому продукту; обязательна ссылка на решение, которое
  побеждает;
- **требует подтверждения** — решение принадлежит владельцу стандарта или
  владельцу программы; до ответа положение остаётся справочным evidence.

### 2.3. Правила, которые матрица не может нарушить

1. приоритет при конфликте — по [`README.md`](README.md) «Иерархия решений»:
   безопасность данных → accepted ADR → Bible → специализированный контракт →
   roadmap. Стандарт как внешний вход стоит **ниже** всех перечисленных;
2. [`ADR_INDEX.md`](ADR_INDEX.md): «Требования Bible не понижаются до уровня
   внешнего входа». Там, где стандарт даёт минимум, а Bible строже, действует
   Bible. Ни одна строка ниже не ослабляет Bible;
3. решение `принять` **не** делает положение нормативным: оно означает, что
   программа приняла это требование **по собственным основаниям**, и при отзыве
   стандарта решение не откатывается;
4. timeout относится только к нормативной силе. На runtime-политику он не
   распространяется: P-14 остаётся fail-closed независимо от статуса стандарта
   (roadmap §6).

### 5.2. Что стандарт даёт программе полезного

Три положения стоит выделить, потому что они не дублируют уже принятое, а
указывают на **незакрытые** обязательства:

1. **ST-25 (backups/PITR).** ADR-0007 §1.1 фиксирует: автоматического
   резервного копирования сегодня нет, off-site backup — ручная операция
   оператора. Стандарт требует backups и PITR безусловно;
2. **ST-47 (перечень обязательных алертов).** `disk space` в этом перечне —
   не гипотеза: заполнение диска 98 % уже наблюдалось (ADR-0008 §1.1);
3. **ST-48 (запрет отправки секретов/ПДн в трекинг ошибок).** Внешне
   подтверждает, что `EXC-0002` — реальное отклонение, а не удобство.

## 6. Проверка условия Gate G0 №10, вторая половина

### 6.1. Метод

Сплошной проход по всем 18 файлам `docs/architecture/adr/ADR-*.md` (0001–0018).

### 6.3. Вывод по второй половине условия G0 №10

**Вторая половина условия выполнена: ни один ADR не ссылается на
неподтверждённое положение стандарта как на обязательное.** Более того,
ADR-0007 §1.1 содержит явное отрицание такой возможности.

Заявлять «условие №10 выполнено» целиком эта задача **не вправе**: у него есть
первая половина — «матрица закрыта либо помечена истёкшим decision timeout»,
и она не выполнена по причине §7. Приёмку выполняет владелец программы.

## 7. Decision timeout: чего нет и почему матрица не закрыта

Roadmap §6 «Decision timeout `W0-STD-01`» требует, чтобы матрица содержала:

1. **дату запроса подтверждения** у владельца стандарта;
2. **decision timeout**, отсчитываемый **от даты отправки запроса**, а не от
   начала работы над матрицей.

Проверено: **в репозитории нет ни одной записи о том, что такой запрос
отправлялся.** Ни в `docs/architecture/**`, ни в расписках, ни в реестре
внешних входов нет ни даты запроса, ни адресата, ни канала. Поиск по шаблонам
«дата запроса», «запрос подтверждения», «отправка запроса», «decision timeout»
даёт только сами правила, но ни одного факта отправки.

Следствия, которые нельзя обойти:

- **отсчёт timeout не запущен.** Timeout считается от даты отправки запроса;
  даты нет — значит нулевой момент не определён и никакой срок не может
  «истечь». Проставить дату задним числом или назначить её от даты этой работы
  означало бы прямо нарушить правило roadmap;
- **матрица не может быть помечена истёкшим decision timeout**;
- **матрица не является закрытой:** шесть положений имеют решение «требует
  подтверждения» (ST-02, 11, 14, 15, 16, 42), и четыре позиции ST-UNK внести
  невозможно;
- поэтому **условие G0 №10 остаётся невыполненным**, и состояние в
  [`G0_READINESS_DELTA.md`](G0_READINESS_DELTA.md) строка 41 («вне компетенции
  интегратора») этой работой не меняется — меняется только то, что теперь
  известно, **что именно** запрашивать.

### 7.1. Что должно произойти, чтобы условие №10 закрылось

Первый шаг принадлежит владельцу программы и никому другому:

1. отправить владельцу стандарта запрос, содержащий: подтверждение
   актуальности редакции v3.1, полный текст (ST-UNK-02), ответ по шести
   позициям «требует подтверждения» и текст «Корпоративных требований к
   идентификации» (ST-UNK-01);
2. зафиксировать **дату отправки** и **величину timeout** — с этого момента
   отсчёт запущен;
3. дальше возможны два исхода, оба закрывают условие: получен ответ — решения
   по шести позициям проставляются и матрица закрывается; ответа нет к
   истечению timeout — матрица помечается истёкшим timeout, неподтверждённые
   положения остаются справочным evidence без нормативной силы
   ([`ADR_INDEX.md`](ADR_INDEX.md), правило 3).

Пункт «поздний ответ владельца входа не переоткрывает принятые ADR
автоматически» (правило 4) действует в обоих исходах.

## 8. Чего эта задача не сделала намеренно

- не проставила дату запроса подтверждения и не запустила decision timeout —
  это действие владельца программы, а не автора матрицы;
- не объявила условие Gate G0 №10 выполненным;
- не восстановила `corp_standard_short_single_vps.md` в рабочее дерево:
  вопрос, должен ли неподтверждённый внешний вход лежать в репозитории,
  принадлежит владельцу программы; адреса blob `8de3f5bc` достаточно, чтобы
  текст не потерялся;
- не изменила реестр внешних входов [`ADR_INDEX.md`](ADR_INDEX.md) и не
  исправила расхождения R-1/R-2 — это правки чужих документов;
- не трогала ADR, [`QUALITY_RUNTIME_CONTRACT_V1.md`](QUALITY_RUNTIME_CONTRACT_V1.md),
  [`G0_READINESS_DELTA.md`](G0_READINESS_DELTA.md), код, тесты, `scripts/**`,
  `.github/**` и чужие расписки;
- ничего не закоммитила.
