# Приёмка источника norm artifact

**Владелец документа:** release/OPS.<br>
**Заполняет:** владелец источника норм.<br>
**Потребитель:** интегратор `W0-INT-01`.<br>
**Контракт:** [quality/runtime contract v1](../architecture/QUALITY_RUNTIME_CONTRACT_V1.md),
§3.3 и §6 (правило 4).<br>
**Инструмент:** `scripts/ci_provision_norms.py`.<br>
**Редакция:** 2026-09-01.

## 0. Статус на дату редакции

Источник **не предоставлен**. Проверено фактами: каталога `norms/vault` нет ни
в дереве, ни в истории git (он в `.gitignore`); у `origin`
(`https://github.com/hoperlex/PDF-proverka.git`) нет ни одного тега и ни одного
релиза (`git ls-remote --tags` пуст, GitHub API отдаёт `[]`); на машине нет ни
одного каталога корпуса, кроме синтетических фикстур pytest. Сработала stop
condition §3 плана волны 0.0.03: пакет A остановлен, `--enforce` в этой волне
не включается.

Wiring при этом уже на месте и ждёт только заполнения этой формы: **править
workflow, чтобы подключить источник, не нужно** — достаточно задать переменные
из §3.

## 1. Что обязан предоставить владелец (форма)

Заполняется целиком. Пустое поле = источник не принят: неполная конфигурация
отвергается CI отдельным кодом (§5), потому что половина конфигурации выглядит
как подключённый источник и опаснее её отсутствия.

| # | Поле | Значение | Пояснение |
| --- | --- | --- | --- |
| 1 | Идентификатор источника | `______` | Короткое имя, попадающее в расписку: `org/norms-vault`, `s3://bucket/prefix`. Требование §3.3 — источник **именованный**. |
| 2 | Владелец источника | `______` | Человек или роль, отвечающая за содержимое корпуса. Не «команда вообще». |
| 3 | Тип источника | `______` | release asset / приватный бакет / отдельный репозиторий / внутренний артефакт-хаб. |
| 4 | Адрес артефакта | `______` | Полный URL. Допускается шаблон с `{version}`. Схема только `https://` или `file://`. |
| 5 | Версия/тег артефакта | `______` | Неизменяемый идентификатор сборки. `latest` не принимается: он делает checksum необъяснимым. |
| 6 | Дата сборки корпуса | `______` | UTC, ISO-8601. |
| 7 | SHA-256 дерева | `______` | 64 hex-символа. Правило расчёта — §2. |
| 8 | Формат артефакта | `______` | `.tar.gz` / `.tgz` / `.tar` / `.zip`, либо каталог для `file://`. |
| 9 | Число файлов и объём | `______` | Для сверки с `vault_file_count` в расписке. |
| 10 | Политика доступа | `______` | Публичный / закрытый. Для закрытого — кто выдаёт доступ и на какой срок. |
| 11 | Способ передачи credential | `______` | См. §4. Значение credential в этот документ **не вписывается**. |
| 12 | Схема авторизации | `______` | `Bearer` (по умолчанию), `token`, `Basic`. |
| 13 | Порядок отзыва доступа | `______` | Что делать при компрометации токена. |
| 14 | Происхождение корпуса | `______` | Откуда взяты тексты норм. Однозначное происхождение — условие §3 плана. |

**Запрещено и приёмку не проходит:** корпус, собранный из
`norms/norms_db.json`, `norms/norms_paragraphs.json` или любого другого
внутреннего файла проекта. `norms/tools/README.md` формулирует это дословно:
«не используем `norms_db.json` как truth или seed». Такой артефакт хуже
отсутствующего — он выглядит как нормативная база, не будучи ею.

## 2. Как считается SHA-256 (правило одно)

Сверяется **дерево**, а не архив: относительный путь каждого файла плюс его
содержимое, файлы в отсортированном порядке. Правило живёт в
`ci_runtime_probe._norm_artifact_digest` и импортируется провижинингом как
есть — второго правила в проекте нет и появиться не должно.

Владелец считает эталон той же командой, которой сверяет CI:

```bash
python scripts/ci_provision_norms.py --digest /путь/к/распакованному/vault
```

Считать сумму своим способом (`sha256sum` по архиву, `find | sha256sum`) —
нельзя: она не сойдётся, и «checksum сошёлся» перестанет что-либо значить.

**Раскладка внутри артефакта.** Пути считаются относительно корня корпуса.
Артефакт с одним корневым каталогом (`vault/СП ...md`) поддерживается: при
распаковке одиночный корень снимается. Файлы норм должны лежать плоско внутри
этого корня — так же, как их ожидает `norms/tools/build_status_index.py`.

## 3. Как это подключается к CI

Переменные репозитория (Settings → Secrets and variables → Actions). Адрес в
workflow не зашит намеренно: зашитый источник — неотзываемое доверие.

| Переменная | Где заводится | Обязательна | Что кладём |
| --- | --- | --- | --- |
| `QR_NORM_ARTIFACT_SOURCE_ID` | Variables | да | поле 1 формы |
| `QR_NORM_ARTIFACT_URL` | Variables | да | поле 4 формы |
| `QR_NORM_ARTIFACT_VERSION` | Variables | да | поле 5 формы |
| `QR_NORM_ARTIFACT_SHA256` | Variables | да | поле 7 формы |
| `QR_NORM_ARTIFACT_TOKEN` | **Secrets** | только для закрытого источника | credential |
| `QR_NORM_ARTIFACT_AUTH_SCHEME` | Variables | нет (по умолчанию `Bearer`) | поле 12 формы |

Шаг `Provisioning norm corpus` в `.github/workflows/ci.yml` уже вызывает:

```
python scripts/ci_provision_norms.py --acquire --build-index --enforce-if-configured --json
```

Смысл `--enforce-if-configured`: строгость привязана к наличию источника, а не
к дате. Пока ни одна переменная не задана — прежнее поведение
(`OPTIONAL_NORM_CORPUS_ABSENT`, exit 0), и ни один исход CI не меняется. С
первой же заданной переменной шаг становится fail-closed: любой сбой получения
— setup failure, а не `::warning::` и не skip.

Порядок действий шага ровно такой, как требует §3.3: получить versioned
artifact → распаковать в staging → сверить SHA-256 → и **только затем** сделать
деревом `norms/vault` и детерминированно собрать `status_index.json`. Не
сошедшийся артефакт корпусом не становится вовсе.

## 4. Credentials

- значение credential не попадает ни в git, ни в этот документ, ни в issue;
- в CI живёт **только** как secret и виден **только** шагу провижининга
  (step-level `env`), а не всему job'у: в окружении pytest его быть не должно —
  §3.1 требует прогон без provider credentials;
- в логи не попадает ни при каком исходе: в расписку пишется лишь факт
  `auth: token|none`;
- адрес публикуется структурно — `scheme://host/<имя файла>`, без query,
  fragment и userinfo. У presigned URL секрет лежит именно в query. Это правило
  P-13 (`scripts/ci_redaction.py`): публикуется признанное безопасным, а не
  всё, что не узнал denylist;
- тексты чужих исключений (urllib кладёт в них полный URL) дополнительно
  проходят `ci_redaction.redact_text`;
- `http://` отвергается конфигурационно: по нему credential уходит открытым
  текстом. Редирект допускается только на `https`, и заголовок `Authorization`
  на редирект не переносится.

## 5. Коды отказа: какой что означает

Все коды машиночитаемы (`failure_reason_code` в `--json`) и общие с
`ci_runtime_probe`/`ci_regression_gate`.

| Код | Что произошло | Кто чинит |
| --- | --- | --- |
| `OPTIONAL_NORM_CORPUS_ABSENT` | Источник **не назван**, корпуса нет. Локально это не ошибка (§3.3). | владелец источника (заполнить форму) |
| `NORM_ARTIFACT_MISSING` | То же состояние в enforce: skip запрещён, отсутствие артефакта — setup failure (§6, правило 4). | владелец источника |
| `NORM_ARTIFACT_SOURCE_MISCONFIGURED` | Конфигурация задана частично или негодна: нет обязательной переменной, схема не `https`/`file`, неизвестный формат, эталон не похож на SHA-256. | тот, кто заводил переменные |
| `NORM_ARTIFACT_SOURCE_UNAVAILABLE` | Источник назван и корректен, но артефакт не отдан: сеть, 401/403/404, таймаут (бюджет 300 с). | владелец источника / доступы |
| `NORM_ARTIFACT_UNPACK_FAILED` | Артефакт получен, но не разворачивается: битый архив, пустой архив, небезопасный путь (`..`, абсолютный), симлинк или не-файл внутри. | владелец источника (пересобрать артефакт) |
| `NORM_CHECKSUM_MANIFEST_MISSING` | Источник назван, а эталона нет: не заданы ни `QR_NORM_ARTIFACT_SHA256`, ни `norms/vault.sha256`. Скачивать нечего сверять. | владелец источника (поле 7) |
| `NORM_ARTIFACT_CHECKSUM_MISMATCH` | Дерево не то, что описано эталоном. Либо артефакт пересобран без обновления суммы, либо повреждён, либо в `norms/vault` уже лежит чужое дерево. | владелец источника |
| `NORM_STATUS_INDEX_MISSING` | Артефакт сверен, производный индекс не построен. Лечится `--build-index`; коммитить индекс нельзя, он производный. | OPS |
| `NORM_INDEX_BUILDER_MISSING` / `NORM_INDEX_BUILD_FAILED` | Сборщик `norms/tools/build_status_index.py` отсутствует или упал. | OPS |

Различие первых двух и `NORM_ARTIFACT_SOURCE_UNAVAILABLE` — принципиальное:
«источник не назван» ждёт владельца, «источник назван и не отвечает» ждёт
починки доступа. Один код на два состояния сделал бы их неразличимыми в
расписке §8.

## 6. Проверка на свежем non-root раннере

Выполняется целиком, по порядку. Расхождение на любом шаге — источник не принят.

```bash
# 0. Свежий чекаут, uid != 0, корпуса в дереве нет.
test "$(id -u)" -ne 0 && test ! -d norms/vault

# 1. Конфигурация источника в окружении (в CI — variables/secrets).
export QR_NORM_ARTIFACT_SOURCE_ID=...   # поле 1
export QR_NORM_ARTIFACT_URL=...         # поле 4
export QR_NORM_ARTIFACT_VERSION=...     # поле 5
export QR_NORM_ARTIFACT_SHA256=...      # поле 7
export QR_NORM_ARTIFACT_TOKEN=...       # только для закрытого источника

# 2. Получение, сверка и детерминированная сборка индекса.
python scripts/ci_provision_norms.py --acquire --build-index --enforce --json
echo "rc=$?"    # обязан быть 0

# 3. Независимая пересверка: состояние без побочных эффектов.
python scripts/ci_provision_norms.py --check --enforce --json
```

Приёмка засчитывается, когда **все** пункты выполнены:

1. шаг 2 вернул `0`, `state.provisioned=true`, `state.checksum_verified=true`;
2. `acquire.norm_artifact_sha256` совпал с полем 7 формы **посимвольно**;
3. `acquire.files` и `vault_file_count` совпали с полем 9;
4. `baseline_allowed=true`;
5. повторный прогон шага 2 даёт **побайтово тот же** `status_index.json`
   (`index_build.status_index_sha256` не изменился);
6. второй раннер, независимо и с нуля, получил **тот же** SHA-256 — иначе
   артефакт не воспроизводим и версия не значит содержимое;
7. в логах обоих прогонов нет ни credential, ни query-строки URL;
8. `git status --short` чист: ни `norms/vault`, ни `status_index.json`,
   ни staging в индекс не попадают.

## 7. Что делает интегратор после приёмки

Порядок — пакет C плана волны, выполняется **после** пакетов A и B:

1. приложить к расписке `W0-INT-01` фактический SHA-256 и вывод §6;
2. прогнать тесты норм и по JUnit разобрать судьбу каждой corpus-зависимой
   записи baseline **по node ID**;
3. пересобрать baseline ровно один раз в том же enforce-окружении
   (`ci_regression_gate.py --record`; он сам откажет без provisioned корпуса);
4. только затем — переключение lanes в `--enforce` и снятие маскировки.

**Предупреждение по шагу 2, установленное фактами волны 0.0.03.** Шапка
`scripts/ci_known_failures.txt` и комментарий в `ci.yml` утверждают, что 33 из
35 записей baseline существуют только из-за отсутствующего корпуса и «обязаны
исчезнуть» после provisioning. Это **неверно**: по свежему JUnit
(`.ci_last_report.xml`) и прямому прогону все 33 записи — это ошибки на setup
фикстуры `tests/test_norms_status_index_fallback.py`
(`AttributeError: module 'norms.external_provider' has no attribute
'NORMS_DB_PATH'`), не зависящие от наличия корпуса. Появление артефакта их не
уберёт. Ожидать «исчезновения 33 записей» как критерия приёмки корпуса нельзя —
это отдельный дефект тестов с другим владельцем. Подробности — в §8.
